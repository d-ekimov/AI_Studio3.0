# Подключение GenAPI к AI Studio

Ключ GenAPI должен находиться только в Supabase Edge Function Secrets под именем `GENAPI_API_KEY`.
Не вставляйте его в HTML, JavaScript сайта, команды терминала, Git или SQL-таблицы.
Авторизация и баланс пользователя не заменяются. Для вложений требуется согласованная миграция, описанная ниже.

## Что сделать в Supabase

1. Откройте **Authentication → Users**. Найдите аккаунт, которым входите в AI Studio, и скопируйте его **User UID**.
2. В **Edge Functions → Secrets** оставьте сохранённый `GENAPI_API_KEY` и добавьте:

   | Имя | Значение |
   | --- | --- |
   | `GENAPI_ALLOWED_USER_IDS` | User UID вашего аккаунта. Несколько UUID разделяются запятыми. |
   | `GENAPI_ALLOWED_ORIGINS` | Origin опубликованного сайта: например `https://d-ekimov.github.io`. Без пути `/AI_Studio3.0/` и без завершающего `/`. |

   Эти два значения — настройки допуска, не дополнительные API-ключи. Если сайт на другом домене, укажите его настоящий origin. Для локальной проверки можно дополнительно указать `http://localhost:5500` через запятую.
3. Создайте Edge Function с именем **`genapi`** через редактор Dashboard.
4. Для Dashboard выполните локально `npm ci`, затем `npm run build:edge`. Замените содержимое серверного `index.ts` содержимым полученного `build/genapi/index.ts`. Это собранная версия двух исходных модулей; вручную переносить их по отдельности не требуется. Зависимости разбора документов загружаются через закреплённые npm-импорты. Секретов в сборке нет.
5. Опубликуйте функцию. Для **этой функции** выключите настройку **Verify JWT with legacy secret**, если она включена. Функция сама обязательно проверяет Bearer JWT через Supabase Auth `/auth/v1/user`, затем User UID и MFA; без сессии доступ запрещён. Конфигурация CLI содержит `verify_jwt = false` по этой же причине.
6. `SUPABASE_URL` и `SUPABASE_ANON_KEY` — встроенные переменные Edge Functions. Не подставляйте вместо них ключ GenAPI.

Альтернатива Dashboard при уже установленном Supabase CLI:

```powershell
supabase login
supabase functions deploy genapi --project-ref zzjfceazpjpavnyyigek
```

Команда выполняется из корня проекта. CLI использует `supabase/config.toml`; секреты уже сохранены в Dashboard.

## Обновление сайта

Опубликуйте изменённые `index.html`, `app.js`, `enhancements.css`, `service-worker.js` и файлы `genapi-client.js`, `genapi-media.js`, `ai-workflows.js`, `chat-attachments.js` вместе.
Обновлённый service worker использует новую версию кеша. Не публикуйте только новый HTML без JS-файлов.
Исходник функции в Git не содержит секретов, но frontend не должен использовать его вместо серверного развёртывания.

## Проверка

1. Войдите в AI Studio аккаунтом из `GENAPI_ALLOWED_USER_IDS`. При включённой 2FA подтвердите TOTP.
2. Статус «Сервер GenAPI настроен» означает проверку окружения и разрешения пользователя, а не проверку баланса или доступности всех моделей у провайдера. Эта проверка не вызывает платную генерацию.
3. Отправьте один короткий запрос в чат и проверьте результат и расход в личном кабинете GenAPI. Реальная генерация оплачивается с баланса GenAPI.
4. Перезагрузите страницу и откройте историю. Если сохранение в Supabase не удалось, интерфейс просит скопировать уже полученный ответ; платный запрос автоматически не повторяется.
5. Проверьте остальные текстовые модели. Сравнение выполняет два запроса, Мульти-ИИ — по одному на выбранную модель.
6. Проверьте Recraft и Eleven v4. Runway Aleph требует публичную HTTPS-ссылку на **исходное видео**; это редактирование видео. Загрузка файлов с устройства в этом этапе не добавлена.
7. Медиа возвращают ID задачи. Подписанный сервером билет привязан к пользователю, модели и ID, действует 24 часа и сохраняется в sessionStorage текущей вкладки. После перезагрузки можно проверить результат. Долговременная история медиа в БД пока не реализована.
8. Сохраняйте медиа на устройство: ссылки GenAPI временные. Закрытие вкладки может удалить локальный билет; задача остаётся в кабинете GenAPI.
9. Проверьте другим аккаунтом: без добавления UID доступ должен быть запрещён.

## Границы первого подключения

### Режимы «Несколько ИИ» и «Мульти-ИИ»

- «Несколько ИИ»: две разные модели получают один и тот же запрос независимо. Для каждого ответа есть статус и копирование; после ошибки можно вручную повторить только эту модель с исходным запросом. Повтор — новый платный запрос. Во время генерации настройки заблокированы. Сравнение с вложениями сохраняется в существующей истории Мульти-ИИ с префиксом «Сравнение:». Сравнение без файлов остаётся в памяти страницы.
- «Мульти-ИИ»: используется существующая история `multi_ai_chats` / `multi_ai_messages`. В последовательном режиме порядок фиксирован: GPT → DeepSeek → Gemini среди выбранных участников. Следующая модель получает успешные предыдущие ответы, а авторы сообщений обозначаются в контексте. В параллельном режиме текущие ответы других участников не передаются.
- Сбой одной модели не останавливает остальных. Платные генерации автоматически не повторяются. Несохранённый ответ остаётся на странице и в памяти текущего диалога, его нужно скопировать перед закрытием страницы. Перезагрузка не восстанавливает ответы, которые не удалось записать в БД.
- Один раунд выполняет по одному платному запросу на выбранную модель. Контекст обрезается до серверных лимитов; полная сохранённая история не изменяется.
- Для мультимодального этапа нужны обновлённая функция, `chat-attachments.js` и миграция ниже. Обновление GitHub само по себе не публикует Edge Function.

При HTTP 404 во всех текстовых моделях проверьте адрес в опубликованной функции:
`https://proxy.gen-api.ru/v1/chat/completions`. Путь `/v1` — базовый адрес, а не рабочий маршрут POST чата.
Если функция опубликована со старым адресом, замените его в редакторе Supabase и нажмите Deploy updates.
Обновление исходника на GitHub не обновляет функцию в Supabase автоматически.

При HTTP 422 во всех медиа-моделях проверьте версию функции: для получения результата
через polling поле `callback_url` должно отсутствовать. GenAPI отклоняет `callback_url: null`
как некорректный URL. Исправленный код не отправляет это поле и при валидации сообщает
названия известных ошибочных параметров без раскрытия ключа или пользовательского ввода.
Для обновления замените код `index.ts` в Supabase и нажмите Deploy updates; frontend менять не требуется.

- Это ограниченный тестовый доступ владельца и явно разрешённых пользователей, не коммерческий публичный запуск.
- Проверки RLS остаются обязательными; миграция вложений добавляет ограничения Storage и проверки ссылок на файлы.
- Демобаланс профиля не используется для оплаты GenAPI. Начисления из браузера не дают права на серверные запросы.
- Текст возвращается целиком, без потока: максимум 2048 выходных токенов, до 40 сообщений и 60000 символов контекста. Старый контекст ограничивается клиентом.
- Внутри одного экземпляра функции действует ограничение 8 генераций в минуту и 3 одновременно. Оно **не является глобальной квотой**: экземпляры Supabase имеют разную память. До публичного запуска нужны постоянный учёт расходов, атомарные квоты и идемпотентные операции.
- Создание платной задачи не повторяется автоматически. При таймауте или разрыве сети проверьте кабинет GenAPI перед повтором: провайдер мог принять запрос.
- Состояние генерации в БД и гарантированное восстановление после сбоев потребуют отдельно согласованной миграции.
- Смена модели в старом обычном чате не даёт точных исторических метаданных модели на каждом сообщении: существующая схема хранит модель на уровне чата.
- Голос Eleven — Alice, язык ru, Turbo. Recraft — Flash, 1024×1024. Дополнительные параметры можно добавить отдельно.

## Локальные проверки без платных запросов

```powershell
node --test tests/*.test.mjs
```

Тесты используют фиктивные секреты и ответы HTTP. Они не обращаются к GenAPI или живой базе и не заменяют проверку развёрнутой функции в Deno/Supabase.

## Вложения: состояние Supabase

10 ноября 2026 года в проекте `zzjfceazpjpavnyyigek` через SQL Editor применена согласованная миграция `supabase/migrations/202611100001_chat_attachments.sql`: приватный bucket `chat-attachments`, поля `attachments` в `ai_messages` и `multi_ai_messages`, правила Storage и триггеры проверки ссылок на файлы. Новые таблицы сообщений не создавались. Выполнены восемь проверок из `supabase/tests/attachments-rls.sql` с откатом тестовых записей.

**Не запускайте эту миграцию повторно на данном проекте:** политики и триггеры уже существуют. Dashboard SQL Editor не записывает её автоматически в историю миграций CLI; перед будущим `supabase db push` необходимо сверить удалённое состояние и отметить уже применённую версию в истории CLI. Не выполняйте массовый `db push` вслепую.

Для другого проекта сначала выполните `supabase/preflight-attachments.sql` и проверьте существующие таблицы/политики, затем примените миграцию один раз.

Лимиты: четыре файла на сообщение, 10 МиБ каждый и 20 МиБ суммарно. В контексте генерации — до восьми уникальных файлов и 20 МиБ. PNG/JPEG/WEBP приводятся к изображению до 2048 px; GIF — первый кадр PNG. Для GPT/Gemini PDF передаётся как файл, для DeepSeek извлекается текст. DOCX/TXT/CSV/XLSX/PPTX обрабатываются на сервере. Формулы таблиц не выполняются, изображения Office не извлекаются. Извлечённый текст ограничен 24000 символами с явной отметкой сокращения.

Файлы загружаются под путём `user_id/chat|multi/chat_id/file_id.ext`. Edge Function проверяет реального пользователя через Supabase Auth, владение родительским чатом и скачивает байты с пользовательской сессией. Постоянные публичные ссылки и service-role ключи не используются. Перед платным запросом сообщение со ссылками сохраняется в БД; при ошибке загрузки или сохранения генерация не запускается.
